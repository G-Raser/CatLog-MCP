# Remote access

CatLog MCP defaults to loopback. Remote MCP clients need a secure path to it.

## Preferred pattern

~~~text
remote MCP client
  -> HTTPS endpoint
  -> restricted reverse proxy / tunnel / private network
  -> CatLog MCP listener
  -> loopback CatLog Companion
~~~

Only the MCP listener crosses a machine or network boundary.

## Bind host

The generated config defaults to:

~~~json
"bind_host": "127.0.0.1"
~~~

If the reverse proxy or tunnel runs on the same machine, leave the server on loopback whenever possible.

If the tunnel terminates on a different machine and reaches the MCP host over a private network, bind CatLog MCP only to the required private interface. Do not use 0.0.0.0 unless the firewall and surrounding network design make that intentional.

## HTTPS

ChatGPT and many remote MCP clients require an HTTPS endpoint.

Use a domain and certificate managed by the reverse proxy/tunnel layer. Keep the actual deployment domain out of public repository examples.

## Authentication and browser origins

CatLog MCP supports an optional shared bearer token. Configure it with `bearer_token` in the external config or, preferably, inject it through `CATLOG_MCP_BEARER_TOKEN`. Tokens shorter than 24 characters are rejected. Only enable this when the MCP client can send an `Authorization: Bearer ...` header.

Browser requests carrying an `Origin` header are denied unless the exact origin is listed in `allowed_origins` or the comma-separated `CATLOG_MCP_ALLOWED_ORIGINS` environment variable. An empty allowlist is deliberate: normal server-to-server MCP traffic usually sends no `Origin`, while unexpected browser cross-origin traffic is blocked.

The randomized MCP path generated by setup.ps1 remains useful as an unguessable routing secret, but path secrecy alone is not a complete Internet security design.

Recommended protections, from strongest to weakest:

1. private network reachability
2. upstream identity/access control compatible with the MCP client
3. optional CatLog MCP bearer token when supported by the client
4. strict reverse-proxy allow rules
5. randomized endpoint path as an additional secret

Never publish the real randomized path or bearer token.

## Do not expose Companion

The Companion is a privileged local bridge to the user's browser-authenticated archive workflow.

It should stay on 127.0.0.1 and should not be routed through the public tunnel.

## Verification after changing networking

1. local Companion health works
2. local CatLog MCP health works
3. remote HTTPS health works without leaking private Companion details
4. MCP initialize works
5. tools/list returns six tools
6. catlog_status reports Companion healthy
7. one real archive succeeds
